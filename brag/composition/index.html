Maya is moving her weather station pipeline from IDL to Python.
The new output has to match the old. One to one.
She runs both and compares. Every single row differs.
IDL works in 32-bit floats. Python works in 64.
So the same humidity comes out two ways.
IDL wrote minus 999 for a missing reading. Python writes nothing.
She renamed temp to temperature_c, so a match by name quietly leaves it out.
And she fixed a real IDL bug. Station S3 had the wrong elevation, so its pressure changed on purpose.
Somewhere in all of that, the port has a bug of its own.
Which differences are fixes, and which are corruption?
Veridelta compares two datasets on their keys, under rules you declare.
Nothing is forgiven unless a rule says so.
Maya declares the rename. Then veridelta suggest reads the data and proposes the rest.
One rule for humidity: a tiny tolerance, and minus 999 as missing. It explains all 124 rows.
No model is called.
The pressure fix was on purpose, so a baseline accepts those 31 rows. Only those.
What's left is the real bug. Four cold readings lost their minus sign.
They were in the first rows all along.
The run fails, and in CI, so does the pull request.
She fixes the port. It passes. One to one.
